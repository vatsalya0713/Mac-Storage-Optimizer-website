When a Mac refuses to delete something, the error message tells you why — once you know how to read it. Work through the fixes below from top to bottom; most problems are solved in the first two steps.

## 1. “The operation can’t be completed because the item is in use”

An app still has the file open.

- **Quit the app** that last used it (<Kbd>⌘</Kbd> <Kbd>Q</Kbd>), not just its window.
- If you don’t know which app, open **Terminal** and ask macOS:

```bash
lsof ~/Downloads/video.mov
```

The output names the process; quit it, or end it from **Activity Monitor**.
- Still stuck? **Restart** your Mac and delete the file before opening anything else.

## 2. The file is locked

Locked files can’t be moved to the Trash (or the Trash asks for confirmation every time).

1. Select the file and press <Kbd>⌘</Kbd> <Kbd>I</Kbd> (Get Info).
2. Untick **Locked** under General.
3. Delete it as usual.

For many files at once, Terminal removes the lock flag:

```bash
chflags -R nouchg ~/Desktop/OldProject
```

## 3. “You don’t have permission” errors

You need write permission for the file **and** for the folder that contains it.

1. Press <Kbd>⌘</Kbd> <Kbd>I</Kbd> on the file (or its folder).
2. At the bottom, open **Sharing & Permissions**, click the padlock and enter your password.
3. Set your user to **Read & Write**, then try again.

Files copied from another Mac, an external drive or a backup often carry the old owner’s permissions — this fixes most of them.

## 4. Use “Delete Immediately”

When the Trash itself is the problem, skip it: select the file and press <Kbd>⌥</Kbd> <Kbd>⌘</Kbd> <Kbd>⌫</Kbd>, then confirm. See our [permanent delete shortcut guide](/blog/how-to-permanently-delete-files-mac) for all the options.

## 5. Restart in Safe Mode

Safe Mode loads only what macOS needs, so nothing else can hold your file open — and it clears some system caches.

- **Apple silicon:** shut down, press and hold the power button until “Loading startup options” appears, select your disk, hold <Kbd>⇧</Kbd> and click **Continue in Safe Mode**.
- **Intel:** restart and hold <Kbd>⇧</Kbd> until the login window appears.

Delete the file, then restart normally.

## 6. Force delete from Terminal (last resort)

```bash
rm -f ~/Downloads/stubborn-file.zip
```

Terminal deletes permanently, with no Trash and no confirmation. Double-check the path; never run `rm` on anything in `/System`, `/Library` or a folder you don’t recognise. Prefixing `sudo` gives it administrator rights — only use that for files you created yourself in a protected location.

## The Trash won’t empty

- **Hold Option** while choosing **Empty Trash** (or press <Kbd>⌥</Kbd> <Kbd>⇧</Kbd> <Kbd>⌘</Kbd> <Kbd>⌫</Kbd>). This skips locked-item warnings.
- **Unlock** any locked items inside the Trash (Get Info → untick Locked).
- **Eject** disks or USB drives whose files are in the Trash — or empty the Trash with the drive connected, because files from external drives stay on that drive.
- **Restart**, then empty the Trash again.
- Still failing? Run **Disk Utility → First Aid** on your startup disk to repair directory errors.

More options are in our [empty Trash guide](/blog/empty-trash-mac-shortcut).

## Files you should not force delete

Some files can’t be removed because macOS protects them with **System Integrity Protection (SIP)** — anything in `/System`, `/usr` (except `/usr/local`) and the apps that ship with macOS. Don’t disable SIP to delete them: they are part of the operating system, and removing them can stop your Mac from starting. If you think system files are taking up space, it’s almost always caches, snapshots or backups instead — see [what’s really inside System Data](/clear-system-data-mac).
